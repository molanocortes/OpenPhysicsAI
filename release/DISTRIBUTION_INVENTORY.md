# Distribution inventory and open licensing decisions (0.3.0-rc2)

Prepared on 2026-09-17 during the independent evaluation. **No licence has been assigned, and nothing was
relicensed.** This file lists what exists, where each item came from, and the decisions only the owner can make.
Nothing may be published until those decisions are made.

## 3. Decisions for the owner

1. **Project licence:** choose one. It must also cover the documentation, the example and task geometry, the test
   scripts and the evaluation records, or state separate terms for them.
2. **Copyright holder and attribution line** for `NOTICE.md` and the binaries' `--version` output.
3. **Material library:** confirm that the demonstration records may be distributed as they are, or replace them with
   values from a source whose terms allow redistribution. Also decide whether a named source should be cited per
   record.
4. **Reference shapes** in `models/` (Ahmed body, airfoil): confirm the references followed, if the GUI is ever
   distributed.
5. **Evaluation records:** decide whether `release/evaluation/` is published with a release (it contains CalculiX
   decks, output extracts and machine-specific paths in some logs) or kept internal.
6. **Third-party tool guidance:** whether the documentation may point users to install CalculiX, NumPy and an MCP
   client (as it does now), and with what wording about their licences.
7. **Trademarks:** "NAVIER" as a product name, and the names of MCP clients in `doc/AI_CLIENTS.md`, should be
   checked before public distribution.
8. **Code signing and notarisation** for macOS: required for distribution beyond internal testing (quarantine
   workaround in `doc/INSTALL.md`). This needs an Apple Developer account, which belongs to the owner.

## 4. Consistency checks for the evaluated artefact

`tools/install_test.sh dist/navier-0.3.0-rc2-macos-arm64.tar.gz` verifies:
- every file against `SHA256SUMS`;
- the documents and the user-test kit are present, without its facilitator reference;
- `VERSION`, the example's expected output and the record format agree;
- no developer paths are in the binaries;
- `doctor` passes in a fresh home;
- the example reproduces the expected output bitwise;
- the replay reproduces;
- the scripted MCP cases pass against the installed server.

The results for the evaluated artefact are recorded in `evaluation/EVALUATION_RECORD.md`.
