# Challenges: measured reality against any simulation

The engine of this project is competition against measurements. A challenge is a fixed question with public
inputs, real measured outcomes, a pre-registered scoring rule and a machine-checked entry format. **Any solver may
enter**, this project's or anyone else's; the leaderboard is the standard, the code here is one reference entry.
Up: [AGENTS.md](../AGENTS.md) · why: [VISION.md](../VISION.md). The thirteen [flags](../README.md) are the project's main
competition now; the challenges here came before them.

| Challenge | Question | Data | State |
|---|---|---|---|
| [nist-am-bench](nist-am-bench/CHALLENGE.md) | NIST's published AM benchmark measurements (bridge distortion, residual strain) | NIST AM-Bench 2018 and 2022 | being imported (T11) |

Rules common to every challenge:

1. **Pre-registration.** The scoring rule and the split between calibration and prediction are written before any
   entry exists and change only by dated amendment.
2. **Declaration and replay.** Every result file says which measurements entered it; every entry names its commit
   and command; scorers rerun entries. Unreproducible entries are listed as unverified, never ranked.
3. **Provenance.** No unit-less or source-less number enters. The scorer refuses rather than guesses.
4. **Categories, not one number.** Open, laptop class, and reference (non-predicting models listed for comparison).
5. **Honest scatter.** Where the measurement uncertainty is unknown, the board says that small differences are not meaningful.

How to add a challenge: write a `challenge.json` in the form `tools/leaderboard.py` reads (its docstring lists the
rules it implements), point it at measured data with a source, write the `CHALLENGE.md`, pre-register the split, and
open a pull request. The first challenges, built on LPBF cantilever measurements, were removed before publication by
the owner's decision; no challenge with measured data is open in this repository today. Measurements you made yourself are the most valuable
contribution this project can receive: see [validation/contrib/README.md](../validation/contrib/README.md).

There is also the **[agent leaderboard](agents/README.md)**: which model, with which tool, solved which physics task
and at what cost. The **[measurement kit](../kit/README.md)** is how a printer owner adds a machine to the boards.

Leaderboards are generated by `make leaderboard` (`tools/leaderboard.py`) from the result files, as Markdown next to
each challenge and as one static page in `docs/leaderboard/index.html`.
