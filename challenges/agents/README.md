# The agent leaderboard: which model pushed the physics, and how far

Every open task in [TASKS.md](../../TASKS.md) has an acceptance test. This board records who solved which task: the
model, the agent tool, the date, the cost and the wall time, and whether the acceptance test passed on replay. It is
a benchmark for AI agents on real engineering work, and it is the mechanism by which every new model release pushes
this software one step further: run the new model against the open tasks, record the run, and the board says what
changed. Up: [challenges/README.md](../README.md). Board: [AGENT_LEADERBOARD.md](AGENT_LEADERBOARD.md) (generated by `make leaderboard`).

## How to record a run

One JSON file per attempt in `challenges/agents/runs/`, named `<date>-<task>-<model>-<short>.json`, from
[run_template.json](run_template.json). Required: the task id, the model name and version as its provider names it,
the agent tool and version, the prompt used (the task text, plus anything you added), the commit the work landed on,
whether the task's acceptance test passed when a maintainer reran it, wall time, and cost if known. Honest partial
results are welcome: a run that reached step 3 of 5 is recorded as that.

## Rules

- The acceptance test is the judge, rerun by a maintainer from the commit. A run whose commit does not pass is
  listed as "not reproduced", never as solved.
- The prompt is part of the record. Extra hints given to the agent are part of the prompt.
- Human edits after the agent finished are declared; a run with undeclared human edits is removed.
- Cost and time are self-reported; the board says so.
- The board ranks by tasks solved, then by cost. It never claims one model is better than another beyond these tasks.

## Physics tasks are the point

Tasks here are not toy problems: each one is a piece of a simulator that is checked against closed forms and, where
the data exists, against measured reality. Solving one changes what the software can predict.
